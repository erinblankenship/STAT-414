6  Cluster Sampling

So far we’ve talked about two sampling designs in detail: simple random sampling (SRS) and stratified random sampling. Sometimes, however, it’s impossible (or at least very difficult) to collect an SRS or stratified random sample. This could be due to many things, including

  • cost (in time or money)
  • lack of a sampling frame for the target population from which to draw our sample

6.1 One-Stage Cluster Sampling

We’re going to start with one-stage cluster sampling. One-stage means





Here’s the set-up:

  • Divide the population into \(N\) clusters, also known as (PSUs).
  • Cluster \(i\) has size \(M_i\), so \(M_i\) is the number of (SSUs).



  • Clusters can be selected using any sampling design. We’ll assume an SRS.
  • On each SSU in a selected PSU, the characteristic of interest is observed. We are back to 2 subscripts:



We’ve got lots of new notation, which we’ll break up by sampling level in addition to population/sample.

Population Quantities: PSU level

\[ \begin{array}{ll} N \hbox{\hspace{70mm}} & t_i \hbox{\hspace{70mm}} \\ & \\ & \\ M_i & t \\ & \\ & \\ M_0 & \sigma^2_t \end{array} \]

Population Quantities: SSU level

\[ \begin{array}{ll} \bar y_{\mathcal{U}} = \frac{1}{M_0} \sum_{i=1}^N \sum_{j=1}^{M_i} y_{ij} & \hbox{\hspace{100mm}} \\ & \\ \bar y_{i\mathcal{U}} = \frac{1}{M_i}\sum_{j=1}^{M_i} y_{ij} = \frac{t_i}{M_i} & \\ & \\ \sigma^2 = \frac{1}{M_0-1} \sum_{i=1}^N \sum_{j=1}^{M_i} (y_{ij} -\bar y_{\mathcal{U}})^2 & \\ & \\ \sigma^2_i = \frac{1}{M_i-1} \sum_{j=1}^{M_i} (y_{ij} - \bar y_{i\mathcal{U}})^2 & \\ & \\ \end{array} \]

Sample Quantities

\[ \begin{array}{ll} \mathcal{S} = \hbox{sample of PSUs from the whole population} & \hbox{\hspace{80mm}} \\ & \\ \mathcal{S}_i = \hbox{sample of SSUs selected from PSU } i & \\ & \\ n = \hbox{number of PSUs in the sample} & \\ & \\ m_i = \hbox{number of SSUs from PSU } i \hbox{ in the sample} & \\ & \\ \bar y_{i} = \frac{1}{m_i} \sum_{j \in \mathcal{S}_i} y_{ij} & \\ & \\ \hat t_i = \frac{M_i}{m_i} \sum_{j \in \mathcal{S}_i} y_{ij} & \\ & \\ s^2_t = \frac{1}{n-1} \sum_{i \in \mathcal{S}} \left ( \hat t_i - \frac{\sum_{i \in \mathcal{S}} \hat t_i}{n} \right )^2 & \\ & \\ s^2_i = \frac{1}{m_i-1}\sum_{j \in \mathcal{S}_i} (y_{ij} - \bar y_i )^2 & \\ & \\ w_{ij} = \hbox{sampling weight for SSU } j \hbox{ in PSU } i & \\ \end{array} \]

Like with previous designs, each unit has a sampling weight. Sampling weights are associated with SSUs.

Let \(w_{ij}\) be the weight for observation unit (SSU) \(j\) in PSU \(i\).




\[ \sum_{i \in \mathcal{S}} \sum_{j=1}^M w_{ij} = \sum_i \sum_j \frac{N}{n} = \sum_i \frac{N}{n}\sum_j 1 = \sum_i \frac{N}{n}(M) = \frac{NM}{n} \sum_{i \in \mathcal{S}} 1 = \frac{NM}{n}(n) = NM \]

Sample weights can be used just like they are in the SRS to calculate estimators:

\[ \hat t = \sum_i \sum_j w_{ij}y_{ij} \hbox{ and } \hat{\bar y} = \frac{\sum_i \sum_j w_{ij} y_{ij}}{\sum_i \sum_j w_{ij}} \]

Survey packages use these weights to get the estimates, just as with other designs.

In R, the main thing that will change is in the svydesign statement. The id option identifies clusters, so now we will use that. With previous designs, our R code looked like:

design<-svydesign(id=~1,weights=~sampwt,fpc=rep(N,n),data=dataset)

with potentially a strata= option included. Now, our generic syntax will be

design<-svydesign(id=~cluster,weights=~sampwt,fpc=~fpc,data=dataset)

where cluster is the column identifying the PSU in the data set.

6.1.2 Unequal size clusters

Often clusters are not the same size (for example, household sizes) so frequently we need to account for the cluster size. Recall that


We could use the same (unbiased) estimators we did when cluster sizes are all equal:

\[ \hat t_{unb} = \frac{N}{n}\sum_{i \in \mathcal{S}} t_i \hbox{ with } \hbox{SE}(\hat t_{unb}) = N \sqrt{\left (1 - \frac{n}{N}\right ) \frac{s_t^2}{n}} \] and

\[ \hat{\bar y} = \frac{\hat t_{unb}}{M_0} \hbox{ with } \hbox{SE}(\hat{\bar y}) = \frac{N}{M_0}\sqrt{\left (1 - \frac{n}{N}\right ) \frac{s_t^2}{n}} \]

These aren’t usually the estimators we use, though. Why not? Why is it important to account for cluster sizes? Typically, cluster total \(t_i\) is correlated with cluster size \(M_i\)




We know how to deal with this situation!

So now, \(M_i\) serves as our auxiliary variable and our response is \(t_i\). We can then use our ratio estimate for population mean, and its corresponding variance estimate

\[ \hat{\bar y_r} = \frac{\sum_{i=1}^n t_i}{\sum_{i=1}^n M_i} \]

with

\[\begin{eqnarray*} \widehat{\hbox{Var}(\hat{\bar y_r})} &=& \left (1 - \frac{n}{N} \right )\frac{1}{n\bar M_{\mathcal{U}}^2} \frac{\sum_{i=1}^n (t_i - \hat{\bar y_r} M_i)^2}{n-1} \\ &=& \left (1 - \frac{n}{N} \right )\frac{1}{n\bar M_{\mathcal{U}}^2} \frac{\sum_{i=1}^n M_i^2 (\bar y_i - \hat{\bar y_r})^2}{n-1} \end{eqnarray*}\]

We can extend the idea of sample weights to different cluster sizes. We’re still in 1-stage clustering, so all SSUs are observed for a selected PSU. This means

\[ w_{ij} = \frac{1}{\hbox{P(SSU } j \hbox{ in PSU } i \hbox{ is in the sample})} = \frac{1}{n/N} = \frac{N}{n} \]

When all clusters are the same size

\[ \sum_{i \in \mathcal{S}} \sum_{j \in \mathcal{S}_i} w_{ij} = NM = M_0 \]

But when the PSUs have different sizes, \(\sum_i \sum_j w_{ij}\) estimates population size:

\[ \sum_{i \in \mathcal{S}} \sum_{j \in \mathcal{S}_i} w_{ij} = \sum_i \sum_j \frac{N}{n} = \sum_{i \in \mathcal{S}} \frac{N}{n} \sum_{j \in \mathcal{S}_i} 1 = \sum_{i \in \mathcal{S}} \frac{N}{n} M_i = \frac{N}{n} \sum_{i \in \mathcal{S}}M_i = \hat M_0 \]

The weights can be used to get estimators in exactly the same way, and this is what survey packages do.

6.2 Two-Stage Cluster Sampling

In two-stage cluster sampling, not all of the SSUs are observed for a selected PSU. Instead,

  • Stage 1: Select clusters (PSUs)

  • Stage 2: Select elements within each selected cluster (SSUs)

and we only collect data on the SSUs that were sampled from the cluster. Here’s what two-stage cluster sampling looks like







Now, because there are two stages of sampling, there are two sets of sampling units.

  • Stage 1: Select SRS of \(n\) PSU from the population of \(N\) PSUs

  • Stage 2: Select SRS of \(m_i\) SSUs from the \(M_i\) elements of PSU \(i\)

What are the implications?

With one-stage cluster sampling, we had data on every single element in the selected clusters

\[ \Rightarrow \hbox{Cluster population values are known. We directly observe } \bar y_i, t_i \]

But with two-stage cluster sampling, we only observe data on a sample of the elements in a selected cluster.

\[ \Rightarrow \hbox{We have to calculate estimates of } \bar y_i, t_i \]

So why use two-stage cluster sampling?

  • Maybe we only have access to a frame that lists clusters

  • Elements in a PSU are so similar that it’s a waste of resources to sample all of them. Extra effort does not provide much additional information.

As you can maybe guess, the variance estimates in two-stage cluster sampling are a LOT messier because we have to account for variance among the PSU (like before) but also the variance among the SSUs within the PSUs.

Let’s consider the unbiased estimator of the population total

\[ \hat t_{unb} = \frac{N}{n} \sum_{i \in \mathcal{S}} t_i \]

We now no longer know \(t_i\), and we have to estimate it. We’ve observed data on \(m_i\) elements in cluster \(i\), so

\[ \hat t_i = M_i \bar y_i = \sum_{j=1}^{m_i} \frac{M_i}{m_i} y_{ij} \]

Basically, we’re using the same estimator we did with one-stage clustering, but plugging in estimated cluster totals rather than known cluster totals.

  • One-stage: \(\hat t_{unb} = \frac{N}{n} \sum_i \underbrace{t_i}_{\text{known}} = \frac{N}{n} \sum_i M_i \underbrace{\bar y_{i\mathcal{U}}}_{\text{known}}\)

  • Two-stage: \(\hat t_{unb} = \frac{N}{n} \sum_i \underbrace{\hat t_i}_{\text{est}} = \frac{N}{n} \sum_i M_i \underbrace{\bar y_i}_{\text{est from } m_i \text{ elements}}\)

The variance of \(\hat t_{unb}\) has two components, associated with the 2 sampling stages: variation among PSUs and variation among SSUs within PSUs:

  • One-stage: only variation among PSUs

\[ \widehat{\hbox{Var}(\hat t)} = N^2 \left (1 - \frac{n}{N} \right ) \frac{s_t^2}{n}, \hbox{\hspace{5mm}} s^2_t=\frac{1}{n-1}\sum_i \left (\underbrace{t_i}_{\text{known}} - \frac{\hat t}{N} \right )^2 \]

  • Two-stage: we now have to estimate \(t_i\) with \(\hat t_i\)

\[ \widehat{\hbox{Var}(\hat t_{unb})} = \underbrace{N^2 \left ( 1- \frac{n}{N} \right ) \frac{s^2_t}{n}}_{\text{among PSUs}} + \underbrace{\frac{N}{n}\sum_{i \in \mathcal{S}} \left ( 1-\frac{m_i}{M_i} \right ) M_i^2 \frac{s_i^2}{m_i}}_{\text{within PSUs}} \]

where \(s_t^2 = \frac{1}{n-1}\sum_{i \in \mathcal{S}} \left ( \hat t_i - \frac{\hat t_{unb}}{N} \right)^2\) and \(s_i^2 = \frac{1}{m_i-1} \sum_{j \in \mathcal{S_i}} (y_{ij} - \bar y_i)^2\).

Why do the unbiased estimators and their variances match so closely with the (biased) ratio estimators? There is little variance among cases and cans and the clusters are all the same sizes.

When should we use the unbiased estimators versus the (biased) ratio estimators? Some things to keep in mind:

  • Unbiased estimation requires that we know \(N\) and \(M_0\).
  • Ratio estimation only requires knowledge of \(M_i\)
  • Unbiased estimation can have poor precision (big variance) if
    • Cluster sizes (\(M_i\)) are unequal
    • Cluster totals (\(t_i\)) are roughly proportional to cluster size
  • Ratio (biased) estimation can be precise if
    • \(t_i\) is roughly proportional to \(M_i\)

Example: (Example 5.9 in book) We want to estimate the average number of legs on healthy puppies in animal shelters. There are two animal shelters in the town. Shelter A has 30 puppies and Shelter B has 10 puppies. We select one shelter at random. After selecting the shelter, we’ll select 2 puppies at random.

Pick Shelter A: \(y_{A1}=4\), \(y_{A2}=4\)

\[\begin{eqnarray*} \hat t_A &=& M_A \bar y_A = (30)(4) = 120 \\ \hat t_{unb} &=& \frac{N}{n}\sum_i \hat t_i = \frac{2}{1}(120)=240 \\ \Rightarrow \hat{\bar y_{unb}} &=& \frac{\hat t_{unb}}{M_0} = \frac{240}{40} = 6 \hbox{ puppy legs!} \end{eqnarray*}\]

Pick Shelter B: \(y_{B1}=4\), \(y_{B2}=4\)

\[\begin{eqnarray*} \hat t_B &=& M_B \bar y_B = (10)(4) = 40 \\ \hat t_{unb} &=& \frac{N}{n}\sum_i \hat t_i = \frac{2}{1}(40)=80 \\ \Rightarrow \hat{\bar y_{unb}} &=& \frac{\hat t_{unb}}{M_0} = \frac{80}{40} = 2 \hbox{ puppy legs!} \end{eqnarray*}\]

So the estimator is unbiased (6+2/2=4), but gives ridiculous estimates (not shown, but the variance of the unbiased mean here is 6400).

The ratio estimator on the other hand,

Shelter A: \(\hat{\bar y_r}=\frac{\sum_i \hat t_i}{\sum_i M_i} = \frac{120}{30} = 4\)

Shelter B: \(\hat{\bar y_r}=\frac{\sum_i \hat t_i}{\sum_i M_i} = \frac{40}{10} = 4\), and the variance is 0.

Let’s go back to the estimator for the population total

\[\begin{eqnarray*} \hat t_{unb} &=& \frac{N}{n} \sum_i \hat t_i = \frac{N}{n} \sum_i M_i \bar y_i = \frac{N}{n} \sum_i \frac{M_i}{m_i} \sum_{j=1}^{m_i} y_{ij} \\ &=& \sum_i \sum_j \frac{N}{n}\frac{M_i}{m_i} y_{ij} = \sum_i\sum_j w_{ij}y_{ij} \end{eqnarray*}\]

So, the weight for element \(j\) in cluster \(i\) is

\[ w_{ij} = \frac{N}{n}\frac{M_i}{m_i} \]

Is this still an equal probability sample? Let’s look more closely as the inclusion probabilities

  • \(\pi_i = \hbox{P(cluster } i \hbox{ is in the sample)} = \frac{n}{N}\) because clusters are selected in a SRS

  • \(\pi_{j|i} = \hbox{P(element } j \hbox{ is selected GIVEN cluster } i \hbox{ is in the sample)} = \frac{m_i}{M_i} = \frac{\hbox{total selected}}{\hbox{total in cluster}}\)

  • \(\pi_{ij} = \hbox{P(element } j \hbox{ and cluster } i \hbox{ is in the sample)} = \pi_i \pi_{j|i} = \left (\frac{n}{N} \right) \left (\frac{m_i}{M_i} \right ) = \frac{nm_i}{NM_i} \Rightarrow w_{ij} = \frac{NM_i}{nm_i}\)

This is only constant if \(M_i/m_i\) is constant, \(M_i/m_i=c\).

So, if we want a self-weighting design with two-stage clustering

  • Stage 1: Select \(n\) PSUs from \(N\) population PSUs using SRS
  • Stage 2: Choose \(m_i\) proportional to \(M_i\) so that \(m_i/M_i\) is constant. Select the \(m_i\) SSUs using a SRS.
  • The sample weight for SSU \(j\) in Cluster \(i\) is then constant for all elements

What are the implications of \(m_i/M_i\) constant? You have to subsample many more elements in big clusters than in small clusters.

We can use R to get estimates from one-stage clustering with unequal cluster sizes, as well as two-stage clustering. The differences are going to come in the svydesign statement, and the inputs we pass to it.

For one-stage clustering with unequal cluster sizes, nothing really changes from equal cluster sizes.

Example: (Book Problem #8) A person with a large library needs to estimate the purchase cost and replace value of a book collection for their insurance. They have 44 shelves with books and randomly select 12 shelves. They then count the number of books \(M_i\) on each of the selected shelves, and generate five random numbers between 1 and \(M_i\) for each selected shelf to determine which books to examine. They select the specific books determined by the random numbers and look up the replacement value. The data are in books.csv on Canvas. We’ll estimate total replacement cost for the library as well as average replacement cost per book.

In R, we’ll use the code
